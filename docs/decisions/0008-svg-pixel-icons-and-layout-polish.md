# 0008. CategoryIconのSVGドット絵化とレイアウトの調整

- ステータス: 採用
- 日付: 2026-08-16

## コンテキスト

実デプロイ後の画面確認で、ユーザーから次のフィードバックがあった。

1. 「アイコンに何も表示されないと寂しい」— `CategoryIcon`
   （[decisions/0005](./0005-placeholder-pixel-art.md)）が単一のUnicode文字
   （♥☆⛨⚖♪）をテキストとして描画していたため、`Press Start 2P` や
   フォールバックフォントにそのグリフが無い環境で空白/豆腐（tofu）表示になっていた。
2. 「パソコンで見ると画面がさみしい」— `App` のレイアウトが
   `max-width: 480px` の1枚のウィンドウを黒背景に置くだけだったため、
   ワイドスクリーンでは余白が非常に目立っていた。

併せて、この修正作業でPlaywrightによるブラウザ確認を行った際、
`StatusPanel` のゲージバー（`ParameterBar`）がほぼ潰れて小さな四角にしか
見えていないバグも見つかった。

## 決定

### 1. CategoryIconをフォント非依存のインラインSVGドット絵に変更

`packages/frontend/src/components/CategoryIcon/pixelGrids.ts` に8x8の
0/1グリッドとして各アイコン（HP=ハート、INT=きらめき、財力=コイン、
装備=盾、判断力=木槌、絆=音符）を定義し、`<rect>` を敷き詰めて描画する
方式に変更した。フォントのグリフサポートに一切依存しないため、
環境によらず同じ見た目になる。

デザインはローカルの静的HTML＋Playwrightスクリーンショットで見た目を
確認しながら反復した（見出しレベルの内容と一致するよう毎回スクリーン
ショットで検証: 詳細はコミット時の検証ログ参照）。

### 2. ゲージバーの潰れを修正

`StatusPanel` は `CategoryIcon` と `ParameterBar` を1つのflex行
（`.statRow`）に並べていたが、`ParameterBar` 自身のルート要素に
`flex: 1` が付いていなかったため、内部の `flex:1` なゲージ要素が
「伸びる先の余白」を持てず、ほぼ0幅に潰れていた。`ParameterBar` を
`flex: 1; min-width: 0;` の `.barWrap` で包むことで解消した。

### 3. 背景・レイアウトの調整

- `body` に、複数の `radial-gradient` を敷き詰めた控えめな星空パターンを
  背景として追加（画像アセットなし、CSSのみ）。ワイドスクリーンでも
  「何もない真っ黒」にならないようにした。
- `App` を画面全体に対して縦横中央寄せするフレックスレイアウトに変更し、
  ステータスパネルの上に `life-management RPG` というタイトル見出しを追加。

## 検証

`npm run dev` を起点にした実ブラウザ確認（Playwright、幅1440pxと390pxの
2パターン）でアイコン・ゲージ・背景・タイトルが意図通り表示されることを
スクリーンショットで確認した。既存の自動テスト（コンポーネントのアクセシブル
ロール・ラベルを検証するもの）はすべてグリーンのまま
（`CategoryIcon` は `role="img"` + `aria-label` を維持しているため、
内部実装がテキストからSVGに変わってもテストの変更は不要だった）。

## 結果・影響

- [decisions/0005](./0005-placeholder-pixel-art.md) の「プレースホルダー」
  という位置づけは `CategoryIcon` については実質解消された（本物のドット絵
  になった）。`PixelAvatar` は依然として単色ブロックのプレースホルダーの
  ままで、今回のスコープ外。
- アイコンのデザインは8x8の抽象的なシルエットであり、公式のスプライトシート
  のような精緻さはない。将来的に本格的なドット絵アセットに差し替える場合は
  `pixelGrids.ts` のグリッド定義を置き換えるだけで済む設計にしてある。
