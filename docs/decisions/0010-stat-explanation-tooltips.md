# 0010. ステータス説明ツールチップ

- ステータス: 採用
- 日付: 2026-08-16

## コンテキスト

デプロイ後、ユーザーから「各ステータスの算出法や説明がないとよく分からない」
というフィードバックがあった。画面には `HP 65 / 100` のような数値が並ぶだけで、
それがリポジトリのどの情報からどう計算されたのかを知る手段が、
`docs/design/status-calculation.md` を直接読む以外に存在しなかった。

## 決定

各ステータス行とLVの横に情報アイコン（`InfoTooltip`）を追加し、
説明ポップオーバーを表示するようにした。

### 表示内容の3階層

1. **データ元** — `logs/` `decisions/` など、参照しているリポジトリのパス
2. **算出方法** — 重み付けや「半減点」の考え方を日本語で説明
3. **いまの内訳** — その時点の実際の内訳（連続記録日数、資格数など）

3つめが重要で、「なぜこの点数なのか」に答えられる。この内訳は
`CharacterStatus` の各ステータスが持つ `details` フィールド（もともと
`stats-engine` がデバッグ用途で返していたもの）をそのまま利用しており、
新たなAPI変更は不要だった。

### 説明文を実装から生成する

`statExplanations.ts` は説明文をハードコードせず、`stats-engine` の
`STATUS_WEIGHTS` から重み・半減点・集計期間を読み取って文面を組み立てる。
たとえばHPの「重み60%」「重み40%」「7日」「15件」といった数値は、
すべて計算式の定数に由来する。

これにより、後で重み付けをチューニングした際（
[decisions/0002](./0002-status-calculation-approach.md) の残課題）に、
説明文だけ古い値のまま残るという典型的な不整合が起きない。
テストでも、engine側の重みが説明文に反映されていることを検証している。

### インタラクション設計

ホバーだけでは、タッチ端末では開けず、キーボード操作でも到達できない。
そのため以下の3経路すべてで開くようにした。

- **ホバー**: マウス利用者向け。カーソルが外れれば閉じる
- **クリック/タップ**: 開いた状態で固定（pin）される。タッチ端末の主経路
- **キーボードフォーカス**: トリガーを本物の `<button>` にしてタブ順に含め、
  `aria-expanded` で開閉状態を読み上げられるようにした

固定状態は Escape キーまたは外側クリックで解除する。

### はみ出し対策

画面下部の行ではポップオーバーが下方向に開くと見切れるため、
表示直後に `getBoundingClientRect()` で測定し、
ビューポート下端を超える かつ 上側に十分な余白がある場合のみ、
トリガーの上側に反転させる。「反転しても結局見切れる」状況では
反転しない条件にしてある。

## 検討した代替案

- **ツールチップライブラリ（Floating UI等）の導入**: 配置ロジックは
  堅牢になるが、必要なのは「下に入らなければ上に出す」という1軸の判定のみで、
  依存追加に見合わないと判断した（
  [decisions/0009](./0009-pixel-cat-avatar-and-space-background.md) と同じ方針）。
- **常時表示（アコーディオンや説明文の併記）**: 情報量が多く、
  レトロなステータス画面という見た目を壊すため却下。

## 検証

- ユニットテスト23件を追加（`InfoTooltip.test.tsx` 10件、
  `statExplanations.test.ts` 11件、`StatusPanel.test.tsx` に2件）。
  ホバー/クリック/フォーカス/Escape/外側クリックの各経路、
  `aria-expanded` の遷移、内訳が `details` から反映されることを検証。
- Playwrightで実ブラウザ確認。HP・絆・LV・モバイル（財力）の各ポップオーバーを
  スクリーンショットで目視確認し、最下段（絆）が上方向に反転して
  全文が読めることも確認した。
