# 0004. RetroPalette / PixelFontトークンの設計

- ステータス: 採用
- 日付: 2026-08-15

## コンテキスト

要件定義書は `PixelFont`（トークン）と `RetroPalette`（トークン）を明示的にコンポーネント
カタログの一部として要求していた。「色数を絞ったレトロカラーパレット」「NESライクな配色
ルール」という指定があるのみで、具体的な色コードは決まっていなかった。

## 決定

- `RetroPalette`（`packages/frontend/src/tokens/palette.ts`）として、背景・ウィンドウ・
  枠線・HP(赤)・MP(青)・ゴールド・グリーン・パープルの十数色に絞ったオブジェクトを定義し、
  `retroPaletteCssVars()` で `--rp-*` というCSS変数に変換する。
- コンポーネント側は必ずCSS変数経由（`var(--rp-hp)` 等）で色を参照し、`.tsx`/`.css`内に
  16進カラーコードを直接書かない規約にした（`RetroPalette` オブジェクト自体を除く）。
- `PixelFont` は "Press Start 2P"（Google Fonts）をCSS変数 `--pixel-font` として定義し、
  和文フォールバック（`"MS Gothic", monospace`）を用意。日本語テキスト（ステータス名など）は
  ドット絵欧文フォントでは表示できないため、フォールバックが実質的な表示フォントになる。

## 検討した代替案

- **自作ビットマップフォント**（要件定義の選択肢の一つ）: 和文グリフを含む本格的な
  ドット文字フォントの新規作成は工数が大きく、今回のスコープでは見送り。
  "Press Start 2P" + 和文モノスペースフォールバックで代替した。
- **CSS-in-JSでのトークン管理**: 追加ライブラリが必要になるため、プレーンCSS変数 + TSの
  オブジェクトという最小構成にした。

## 結果・影響

- 色の一元管理により、後から配色を変える場合は `palette.ts` と `global.css` の2箇所
  （本来は1箇所にできるが、Storybookプレビュー用に静的CSSとしても必要なため重複させている）
  を変更すれば全コンポーネントに反映される。
- 和文フォントの本格的なドット絵化は未実施のまま残った既知の制約。
