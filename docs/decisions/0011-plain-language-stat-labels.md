# 0011. ステータス名を「何を測っているか」が分かる日本語に変更

- ステータス: 採用
- 日付: 2026-08-16

## コンテキスト

[decisions/0010](./0010-stat-explanation-tooltips.md) で情報ポップオーバーを
追加したが、ユーザーからさらに次の指摘があった。

> HP、INTとかありますが正直、よくわかりません。
> 例えば、財力なら財力の記録の充実度を示していること、絆はAIとのチャットの
> 回数の記録の数によって決まっていることが分かりやすいですが、他のやつよく分からぬ。

この指摘は問題の本質を正確に突いている。**「財力」「絆」は分かるのに
「HP」「INT」「装備」が分からないのは、前者がラベル自体で測定対象を
説明しているのに対し、後者はRPGの記号でしかない**からである。
ポップオーバーを開けば説明は読めるが、開かないと分からない時点で
一覧性が損なわれている。

## 決定

### 1. ラベルを測定対象そのものを表す日本語名に変更

| 変更前 | 変更後 | 何を測っているか |
|---|---|---|
| HP | **継続力** | `logs/` の記録の継続 |
| INT | **資格力** | `profile/qualifications.md` の資格 |
| 財力 | 財力（変更なし） | `finance/` の記録 |
| 装備 | **生活基盤** | `home/` の記録 |
| 判断力 | 判断力（変更なし） | `decisions/` の記録 |
| 絆 | 絆（変更なし） | `chat-summaries/` の記録 |

ユーザーが「分かる」と評価した2つ（財力・絆）はそのまま残し、
分からないと指摘された3つ（HP・INT・装備）を、同じ「測定対象を名指しする」
命名規則に揃えた。判断力はもともと日本語だが、何のログを数えているのかが
不明瞭だったため次項のヒントで補っている。

### 2. 常時表示の一行ヒントを追加

ラベルの下に、何を数えているのかを説明する小さな一行を常時表示する
（`ParameterBar` の `hint` prop）。

- 継続力 → 日々の記録の続きぐあい
- 資格力 → 取得した資格の数と有効性
- 財力 → お金まわりの記録の充実度
- 生活基盤 → 家電・住まいの記録の数
- 判断力 → 意思決定ログの蓄積数
- 絆 → AIとの対話ログの数

狭い画面（720px以下）では横幅が足りないため非表示にし、
その環境では情報ポップオーバーが説明を担う。

### 3. ポップオーバーの先頭に一文サマリーを追加

[decisions/0010](./0010-stat-explanation-tooltips.md) のポップオーバーは
「データ元 → 算出方法 → いまの内訳」という構成で、いきなり仕組みの話から
始まっていた。その手前に「この数値は何を意味するのか」を答える一文
（`summary`）を追加し、意味 → 仕組み → 実数、の順に読めるようにした。

## 検討した代替案

- **RPG名（HP/INT）を残し、副題として日本語を添える**: RPGらしさは保てるが、
  1行に2つの名前が並んで視線のノイズになり、かつ「結局HPとは何か」という
  疑問は残る。要件定義のRPG感は、ドット絵アイコン・ゲージ・レトロ配色・
  レベルアップ演出で十分に表現できていると判断し、ラベルは実用性を優先した。
- **ヒントを常時ではなくポップオーバーのみに置く**: 既に0010でそうしていて、
  それでも分からないというのが今回のフィードバックだったため却下。

## 結果・影響

- `CategoryIcon` の `aria-label` も新しい名前に統一し、スクリーンリーダー上でも
  ゲージ・アイコン・情報トリガーが同じ呼称になるようにした。
- 「HP」「INT」という呼称はコードの内部識別子（`CharacterStatus` のキー名
  `hp` / `int`、`STATUS_WEIGHTS` のキー）には残っている。これらはAPIレスポンスの
  形状でもあるため、表示名の変更に引きずられて改名すると Worker との契約変更に
  なる。表示層だけの変更に留めた。
- ユニットテスト4件を追加（ヒントの表示/非表示、サマリーの表示、
  全ラベルの疎通）。既存テストのラベル参照も新名称に更新した。
