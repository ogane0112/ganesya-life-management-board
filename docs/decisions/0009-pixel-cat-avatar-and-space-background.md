# 0009. ドット絵猫アバターと宇宙背景アニメーション

- ステータス: 採用
- 日付: 2026-08-16

## コンテキスト

[decisions/0008](./0008-svg-pixel-icons-and-layout-polish.md) の後、ユーザーから
さらなる見た目の要望があった。

1. `PixelAvatar`（当時はレベル帯ごとに色が変わるだけの単色ブロック）を、
   SVGドット絵のかわいい猫にしたい。
   （「Claude Codeのタコ」案は、Anthropic自身のブランド資産を第三者アプリに
   無断で使うことになるため見送り、代わりに猫デザインを提案・実装した）
2. 背景を宇宙っぽく、地球や流れ星が動く派手めなアニメーションにしたい。
   「ある程度安全ならライブラリを使ってよい」との許可も得た。

## 決定

### PixelAvatar: 16x16のインラインSVGドット絵猫

`packages/frontend/src/components/PixelAvatar/catGrid.ts` に16x16の
チビ猫顔グリッドを定義し、`CategoryIcon`と同じ「0/1グリッドを`<rect>`で
描画する」方式で実装した。レベル帯（novice/adept/veteran/legend）ごとに
形状は共通のまま、`RetroPalette`の色（灰/緑/青/金）のみ変える設計にした
（色の意味付けは`ParameterBar`等と揃えてあり、他ステータスの成長と
同じ配色言語で「レベルが上がった」ことが伝わるようにした）。

デザインは`CategoryIcon`と同様、ローカルの静的HTML＋Playwrightスクリーン
ショットで見た目を確認しながら反復した（口の形を平坦な線から猫らしい
曲線に、あご下の余分な帯を削除する、など）。

### SpaceBackground: CSSアニメーション主体、外部ライブラリなし

星空・流れ星・地球を表示する `SpaceBackground` コンポーネントを新設。
**外部の演出/グラフィックライブラリは追加していない**（ユーザーからは
許可があったが、この程度の演出はブラウザ標準機能で十分に実現でき、
追加の依存関係によるバンドルサイズ増加・保守コストに見合わないと判断した）。

- **星**: 1つの要素に大量の`box-shadow`を持たせて多数の星を1レイヤーで
  描画する定番の軽量テクニック。サイズの異なる3レイヤーを少しずつ違う
  タイミングで明滅させることで、まとまった集団明滅でも自然な瞬きに見える
  ようにした。
- **流れ星**: `transform`/`opacity`のCSSキーフレームアニメーションで、
  3本を異なる遅延・軌道でループさせている。
- **地球**: 20x20グリッドで、海（円）は数式で計算し、大陸のみ手動で
  配置した小さな緑ピクセルの集合として重ねている（円を手描きでずらす
  リスクを避けるため）。

### バグ修正: z-indexスタッキングコンテキスト

背景を`position: fixed; z-index: 0`で実装したところ、本文（`<h1>`や
ステータスパネル）が非positioned要素だったため、CSSの重なり順規則上
「positionedな子要素はz-indexの値によらず非positioned要素より後に
描画される」という挙動により、背景がすべての本文を覆い隠してしまう
不具合が発生した。`z-index: -1`（負の値）にすることで、スタッキング
コンテキストの背景レイヤーとして正しく最背面に配置されるよう修正した。
これもPlaywrightでの実描画確認で発見・修正した。

## 検証

`npm run dev` を起点にした実ブラウザ確認（Playwright、幅1440pxと390pxの
2パターン）で、猫アバターの表示・星空/流れ星/地球の表示・本文が背景より
手前に正しく重なることをスクリーンショットで確認した。既存の自動テスト
（`PixelAvatar`のアクセシブルロール・ラベルを検証するもの）はすべて
グリーンのまま。`SpaceBackground`自体は`aria-hidden`な純粋装飾のため
専用のユニットテストは追加していない。

## 追記（2026-08-16）: 構図の作り直し

初回実装をユーザーが実機で確認したところ、次のフィードバックがあった。
「流れ星が流れていない」「PC版だと地球が小さい」「地球に回転や揺らぎが欲しい」
「地球が右側だけにあると不自然で、デザインのバランスが悪い」
「指示しなくてもいい感じのデザインにしてほしい」。

場当たり的な数値調整ではなく、構図の基本原則に沿って作り直した。

### 適用した原則

- **非対称バランス（asymmetric balance）**: 大きな地球を右上、小さな月を
  左下に置き、対角線上で視覚的重みを釣り合わせた。要素が片側だけにある
  状態を解消しつつ、左右対称の退屈さも避けている。
- **視覚的階層（visual hierarchy）**: 画面端を暗くするヴィネットを追加し、
  中央のステータスカードが最もコントラストの高い焦点であり続けるようにした。
  背景は「背景」に留める。
- **奥行き（depth cueing）**: 大きく明るい＝近い、小さく淡い＝遠い、という
  規則で地球・月・3層の星を配置。低彩度のネビュラ雲をさらに奥のレイヤーとして
  加え、真っ黒な平面を避けた。
- **レスポンシブなスケール**: 惑星サイズを`clamp()`＋`vmin`で指定し、
  大画面でも豆粒にならず、モバイルではコンテンツを邪魔しないようにした。

### 技術的な修正

- **地球の自転**: 円形クリップの内側で、大陸だけのタイル可能な帯を
  ちょうど1タイル幅だけ水平移動させることでシームレスにループさせ、
  自転して見えるようにした（`planetGrid.ts`）。加えて明暗境界（terminator）の
  グラデーションで球体感を出し、上下にゆっくり漂う`float-slow`も追加。
- **流れ星が見えなかった問題**: 移動距離が短く、可視区間の大半が画面外
  だった。軌道を画面をしっかり横断する距離に伸ばし、可視時間も長くした。
  併せて尾の角度が進行方向と一致していなかった（進行方向に対して逆向きに
  尾が伸びるべきところ、同じ向きになっていた）ため、移動ベクトルの逆向きに
  合わせて`-23deg`に修正した。

いずれもPlaywrightで複数タイミングのスクリーンショットを撮って
実際に流れ星が可視であること・大陸の位置が時間で変化していること
（＝自転が効いていること）を目視確認した。

## 結果・影響

- [decisions/0005](./0005-placeholder-pixel-art.md) の「プレースホルダー」
  という位置づけは`PixelAvatar`についても実質解消された。
- `prefers-reduced-motion`を尊重し、モーションに敏感なユーザーには
  アニメーションを無効化する（`SpaceBackground.module.css`）。
- 星の座標は`Math.random()`で生成しているため、リロードごとに配置が
  変わる（意図的。決定論的にする必要のある描画ではない）。
- 背景は`aria-hidden`な純粋装飾であり、アニメーションはすべてCSSの
  `transform`/`opacity`（コンポジタで処理される特性）に限定しているため、
  レイアウト再計算を伴わず負荷が低い。
